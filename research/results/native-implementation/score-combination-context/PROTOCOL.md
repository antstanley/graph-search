# Normalized score combination through native source delivery

Frozen before the first response. Compare current native automatic ranking with
the preselected 75% body / 25% metadata min-max combination. The candidate is a
disposable native QueryEngine patch; production is read-only. Use the existing
faithful native-JSON evidence protocol, 58 source-validated tasks, three repeats,
four tool calls, 16 KiB response / 48 KiB cumulative context budgets, eight seeds,
one graph hop, identical source policy and work limits. Alternate arm order.

The generic driver calls the current production arm `structured` and the disposable
patched arm `fixed`. For THIS intervention structured = baseline, fixed = normalized
candidate. Do not reverse reported gains. Both use Auto with diversity disabled.

The previous diagnostic used top 50 per lane. This experiment uses the actual
native pool, currently 64 at k=8. Both lanes pay native work charges; the candidate
does not receive free metadata retrieval. Matching occurrences, owner grouping,
relationship/source selection, graph context and payload fitting retain native
behavior. Scores alter both ordering and the rank prior used by context assembly;
this is an end-to-end policy experiment, not a ranking-only causal claim.

Min-max normalization excludes exact metadata identities and treats nonempty
flat lanes as one; missing lanes contribute zero. Native bounded metadata scores
and native raw body scores are normalized separately. Original body-rank order
still chooses each owner's best source evidence; combined scores choose seeds.
Exact metadata stays in its separate priority tier. Native path/span/id tie order
is retained, unlike the diagnostic's path/id tie order.

The experiment accepts only a clean indexed body lane. A nonempty live-body lane
fails explicitly; do not normalize or add raw scores from different body corpora.
This restricted trial can reject the candidate before broader integration. It
cannot validate publication on stale/mixed generations. No production default or
new public option may follow without separately modeling and testing that case.

Retain all per-task region/file/relationship coverage, source-validity errors,
response bytes, line changes, work counters and repeated-action stability. Promotion
requires at least one complete-region gain without a complete-region loss and
without lower mean region coverage in any repository or task kind. Investigate
every loss regardless of the aggregate. A failed gate keeps the production default;
do not tune weights on these now-exposed labels. No model-success or latency/RSS
claim. All source, executable and sibling CodeGraph fingerprints must remain stable.
